      S3 专项训练
      
        
      RAG 全链路诊断实验室
      
        
      沿十层证据链定位故障，比较二十五条提升路径，并用最小消融、关键阻塞规则和回滚条件决定是否升级。
      
      
      
      
      教学诊断模拟不连接生产语料不调用真实模型项目结论固定到审计 commit
      
      
      
      
      
        
        
        
        
        
      
      

      
      
        
      
          
      01 · 从学习到交付
      RAG × Vibe Coding 七阶段主线
      每一步都给出目标、产物、常见问题和通过门禁。先把反馈闭环跑通，再选择高级方法。
      
          
        
      
        
      
          
      
          
      
        
      
        
      
          
      从来源到发布的十层证据链
      遇到失败时先找证据第一次变坏的位置。越权和注入优先于质量，数据与解析优先于检索调参。
      
          
        
      
        
      
      
      

      
      
        
      02 · 比较而非堆叠
      二十五条提升路径
      每个方法都绑定触发症状、最小实验、指标、成本和回滚；没有失败证据就保留简单基线。
      
        
      
          
      
          
      
        
      
        
      
        
      
          
      
          
      
        
      
      
      

      
      
        
      03 · 选择最小架构
      工作负载架构规划器
      先选强基线，再写明何种失败才允许升级，以及必须共同通过的质量、安全、时效和成本门禁。
      
        
      
          
      
        
      
        
      规划结果只保存在当前浏览器。
      
        
      
      

      
      
        
      04 · 按信号诊断
      十四类故障第一动作
      至少正确完成 4 个场景。答错先讲误区与原理；答对后才展开指标、blocker 和最小实验方向。
      
        
      
          
      
            
      
            
      
            
      
            
      
          
      
          
      
            
      
            
      
          
      
        
      
      
      

      
      
        
      05 · 从源码到维护
      项目源码、资料时效与未来走向
      固定 commit 只证明已实现机制；生产适用性必须由自有数据、威胁模型、成本预算和回滚演练证明。
      
        
      
          
      
          
      
        
      
        
      
        
      
          
      
            
      资料维护状态
      按“当前采用、持续观察、历史基础、已退出主线”分层。历史论文保留原理价值，旧 API 和误导性路线不再作为默认入口。
      
            
          
      
          
      
          
      
        
      
      
      
    
      

    
      
      
      
        
      S5 专项训练
      
        
      Agent Memory 实验室
      
        
      从工作负载出发比较方法、设计最小架构，并把每条候选记忆送过写入、召回、纠错和删除门禁。
      
      
      
      
      教学决策模拟不采集真实数据不连接数据库论文结果不等于生产 SLA
      
      
      
      
      
        
        
        
        
      
      

      
      
        
      
          
      01 · 先比较
      21 类方法与六轴谱系
      同时回答记什么、保留多久、存在哪里、谁控制、如何取回、如何治理，再做产品或框架选择。
      
          
        
      
        
      
        
      
        
      
          
      
          
      
        
      
      
      

      
      
        
      02 · 再选型
      最小架构选择器
      复杂度必须由工作负载和失败证据推动。先做能治理、能评测的最小组合。
      
        
      
          
      
          
      
          
      
          
      
        
      
        
      选择会写入当前浏览器的学习进度。
      
        
      
      

      
      
        
      03 · 做决策
      记忆生命周期演练
      至少正确完成 4 个场景。答错会指出误区；只有正确决策才展示该条记忆的路径与审计证据。
      
        
      
          
      
            
      
            
      
            
      
            
      
          
      
          
      
            
      
            
      
          
      
        
      
      
      

      
      
        
      04 · 用证据验收
      评测基准、工业指标与未来走向
      基准告诉你“在哪类任务上有效”，指标决定“能否进入生产”。未来判断明确区分已有证据与工程推断。
      
        
      
          
      当前基准
      
          
      发布指标
      
        
      
        
      
        
      
          
      八个 GitHub 项目源码审计
      
          
      查看固定 commit、源码入口、已确认机制和不能由仓库直接推断的生产能力。
      
          
      
            
      
            
      
          
      
        
      
      
      
    
      

    
      
      
      
        
      S6 专项训练
      
        
      Agent Eval 与发布门禁实验室
      
        
      把前序能力装入同一发布候选，先验证 Agent，再攻击 grader 与 gate，最终用可复现证据作出 pass 或 block。
      
      
      
      
      教学门禁模拟不调用真实模型不读取私有 holdout本地指标不代表生产 SLO
      
      
      
      
      
        
        
        
        
      
      

      
      
        
      
          
      01 · 建立全链路
      从候选版本到发布判定
      顺序不能颠倒：先固定版本和干净 trial，再看规则、轨迹、裁判、切分与运营预算。
      
          
        
      
        
      
      
      

      
      
        
      02 · 读懂阻塞规则
      风险不能被一个总分压平
      每条规则都绑定触发信号、判定理由和必须保留的证据；非关键差异可以进入 backlog，不必制造过度拒绝。
      
        
      触发信号决策工程理由必须留下
      
      
      

      
      
        
      03 · 亲自作出决策
      发布门禁判定演练
      至少正确完成 4 个场景。答错会指出具体误区；判对后才展示 blocker、证据和该场景经过的门禁步骤。
      
        
      
          
      
            
      
            
      
            
      
            
      
          
      
          
      
            
      
            
      
          
      
        
      
      
      

      
      
        
      04 · 核验证据边界
      一手实践与工业演进
      一手资料支持的变化与工程推断分开呈现；平台 API 可以替换，task、dataset、grader 和证据谱系不能丢。

      S7 专项训练
      
        
      Agent Observability 与事故响应实验室
      
        
      从一次真实 Runtime 运行的轨迹出发，建立信号合同、SLO 和分级响应，再把事故转成有 owner 的回归用例。
      
      
      
      
      可运行教学基线Runtime 轨迹派生 span延迟与成本为固定 fixture不代替生产 OTel 后端
      
      
      
      
      
        
        
        
        
        
      
      

      
      
        
      01 · 先定义信号边界
      Trace、Metric、Log、Audit 和 Replay 各司其职
      不以“记得越多越好”为目标，而是明确每类信号回答的问题、最小证据和保留期。
      
        
      
      
      

      
      
        
      
          
      02 · 沿一次 run 定位
      检查父子 Span 与证据链
      只有能从入口追到终态、政策和副作用的轨迹，才能支撑根因定位和事故重放。
      
          
        
      
        
      
          
      
          
      轨迹验收合同
      
        
      
      
      

      
      
        
      03 · 用用户影响定义 SLO
      分页、工单与观察不是同一件事
      快速预算燃烧要立即止损，慢性退化要绑定 owner，可恢复的单次错误则保留证据并观察趋势。
      
        
      触发信号级别响应工程理由必须留下
      
      
      

      
      
        
      04 · 亲自值班
      事故响应决策演练
      至少正确完成 4 个场景。答错时会展开误区和原理；答对后才显示证据、blocker 和该事故的信号路径。
      
        
      
          
      
            
      
            
      
            
      
            
      
          
      
          
      
            
      
            
      
          
      
        
      
      
      

      
      
        
      05 · 把观测变成持续改进
      一手规范、安全边界与未来走向
      语义规范仍在变化，所以要锁定版本、保留内部证据合同，并将现有证据与工程推断分开。
      
        
      
          
      一手资料
      
          
      当前与未来
      
        
      
      
      
    
      

    
      
      
      
        
      S8 专项训练
      
        
      Agent Security 与 Sandbox 实验室
      
        
      假设模型会被误导，沿九层确定性控制链判断请求应允许、待审批、阻断还是隔离。
      
      
      
      
      可运行控制平面 fixture25 个 critical case不执行真实工具不冒充 gVisor / microVM
      
      
      
      
      
        
        
        
        
        
      
      

      
      
        
      
          
      01 · 约束危险路径
      九层控制链
      Prompt 和 classifier 只降低风险；身份、网络、文件、凭据和执行边界必须由模型之外的系统强制执行。
      
          
        
      
        
      
      
      

      
      
        
      02 · 固定终态
      四种决策，不允许模糊放行
      审批不能覆盖其他安全失败；未知 schema、策略故障和 sandbox 故障必须 fail closed。
      
        
      
      
      

      
      
        
      03 · 亲自判定攻击
      安全响应决策演练
      至少正确完成 4 个场景。答错先说明误区，答对后才显示 reason code 和必须保留的证据。
      
        
      
          
      
            
      
            
      
            
      
            
      
          
      
          
      
            
      
            
      
          
      
        
      
      
      

      
      
        
      04 · 不把产品名当架构
      六个项目的源码边界
      固定 commit 检查隔离、策略和攻击评测实现，同时明确每个项目仍不能替代的企业控制。
      
        
      
          
      
          
      
        
      
      
      

      
      
        
      05 · 区分证据与推断
      一手规范与未来走向
      已公开的规范和工程实践单独列出；工作流凭据、签名 sandbox profile 与 MCP 持续准入仍需生产验证。
