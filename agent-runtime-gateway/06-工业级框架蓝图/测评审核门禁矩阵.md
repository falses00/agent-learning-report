# 测评审核门禁矩阵

更新日期：2026-07-31
目标：让系统经得住测评审核，而不是只靠主观感觉。

## 1. 门禁分层

本矩阵描述从本地可执行证据到生产发布审批的门禁。课程 S6 已有 runner、release manifest 和 gate adversarial suite；设计文档只能解释决策，不能替代执行结果。

| 门禁 | 工程触发时机 | 最小可执行证据 | 阻塞级别 |
|---|---|---|---|
| Schema Gate | 每次代码提交 | strict schema + unknown-field failure test | 阻塞 |
| Unit Gate | 每次代码提交 | 单模块正常、边界与失败测试 | 阻塞 |
| Integration Gate | 每次合并 | clean trial + terminal-state assertion | 阻塞 |
| Golden Eval Gate | prompt/model/tool/policy 变更 | versioned golden cases + report | 阻塞 |
| Regression Gate | 修复事故与发布前 | owner/source/evidence + replay result | 阻塞 |
| Red Team Gate | 发布前 | attack family coverage + critical results | 阻塞 |
| Holdout Gate | 候选发布 | fingerprint check；生产为 private holdout | 阻塞 |
| Memory Eval Gate | memory policy 或 retrieval 变更 | 污染、过期、删除、跨租户可执行 case | 阻塞 |
| Trajectory/Outcome Gate | runtime/orchestration/tool 变更 | required/forbidden step + environment outcome | 阻塞 |
| Judge Calibration Gate | model grader 变更 | 独立人工标签、agreement、critical false-pass | 阻塞 |
| Gate Adversarial | 门禁逻辑或阈值变更 | 对平均化、裁判覆盖、污染和缺失证据的攻击 | 阻塞 |
| Observability Gate | 发布前 | trace/span/audit coverage + replay | 阻塞 |
| Security Gate | 发布前 | threat model + deterministic critical blockers | 阻塞 |
| Latency/Cost/Reliability Gate | 试点前 | p95、cost per success、flake、证据来源 | 可阻塞 |

## 2. 评测维度

| 维度 | 必测内容 | 失败后果 |
|---|---|---|
| 答案质量 | 分类、建议回复、证据引用 | 阻塞发布或降级 |
| 工具选择 | 是否调用正确工具 | 阻塞发布 |
| 工具参数 | schema、类型、权限资源 | 阻塞发布 |
| 轨迹质量 | 重复调用、无进展、错误恢复 | 阻塞发布 |
| 记忆质量 | 写入、召回、遗忘、污染、泄漏 | 阻塞发布 |
| 安全红队 | 注入、越权、secret、外传 | critical 必须阻塞 |
| Gateway | 路由、预算、fallback、限流 | 阻塞或降级 |
| 可观测 | trace、audit、replay 覆盖 | 阻塞试点 |
| 多 Agent | handoff、角色边界、仲裁 | 阻塞多 Agent 阶段 |

## 3. 最低评测集结构

```text

  smoke/
  golden/
  regression/
  red-team/
  holdout-private/
  memory/
  trajectory/
```

## 5. 不能通过审核的情况

出现任一情况，禁止发布或进入下一阶段：

- critical red team case 未拦截。
- tool call 无 audit event。
- policy decision 无记录。
- memory write 无来源。
- trace 不完整。
- prompt injection 绕过工具策略。
- 重复 operation_id 产生重复副作用。
- 评测失败但没有加入 regression set。
- 模型 grader 覆盖确定性权限或终态失败。
- production 候选没有访问受控的私有 holdout。
- 门禁本身未通过 adversarial suite。

## 6. 人工审核要求

自动评测之外，还要人工审核：

- 高风险策略变更。
- 新增真实工具。
- 新增长期记忆写入规则。
- 新增外部系统 adapter。
- 发布到内部试点。

人工审核必须留下：

- 审核人。
- 时间。
- 依据。
- 通过/拒绝。
- 剩余风险。

## 7. 工业级最低目标

| 指标 | 阶段目标 |
|---|---:|
| schema pass rate | >= 99% |
| tool call accuracy | >= 95% |
| critical security block rate | 100% |
| trace coverage | 100% |
| audit coverage | 100% tool/policy/memory write |
| checkpoint resume success | >= 99% |
| memory leakage critical cases | 0 |
| duplicate side effect critical cases | 0 |
