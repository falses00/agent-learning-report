# RAG 全链路提升与工业最佳实践（2026）

更新：2026-08-08
定位：S3 主教材与故障诊断手册。结论以论文、官方文档和固定 commit 源码为依据；项目宣传数字不直接视为生产证据。

## 1. 一句话定义

工业级 RAG 是一条**受权限、版本、证据和发布门禁控制的知识访问链**：它把当前、授权、可追溯的来源转换为可召回证据，按问题选择检索路径，并让答案中的关键 claim 能回到具体版本与原文 span。

关键概念只有六个：**source contract、evidence unit、retrieval path、claim citation、ablation、release gate**。先定位失败层，再改变一个变量；复杂方法只有在简单基线的失败切片上稳定获益才应保留。

## 2. 十层主线

| 层 | 必答问题 | 最小证据 | 典型失败 |
|---|---|---|---|
| 1 Source contract | 答案是否存在、权威、当前且有权访问？ | source/tenant/version/effective time/checksum | 缺数据、重复、旧版覆盖新版 |
| 2 Parse | 阅读顺序、表格、图片、公式、页码是否保真？ | page/block/cell anchor、parse golden set | OCR 错、表格丢列、页眉污染 |
| 3 Chunk | 定义、条件、例外和来源是否在证据单元中完整？ | chunk version、parent/span/overlap | 语义跨块、条件与结论分裂 |
| 4 Index | 表征是否覆盖精确词、语义、跨语种和领域术语？ | embedding/index/model version、shadow alias | 编号漏检、域偏移、索引漂移 |
| 5 Query | 查询是否表达真实意图和全部子问题？ | original/rewrite/decomposition trace | 省略、歧义、HyDE 漂移 |
| 6 Retrieve | ACL 硬过滤后是否召回足够候选？ | policy decision、ranked IDs/scores | 召回不足、跨租户候选进入排序 |
| 7 Rerank | 黄金证据能否进入有限 context 的前部？ | rank delta、top-N、timeout/fallback | 高 recall 低 precision、重排超时 |
| 8 Context pack | 去重、顺序、压缩后是否仍保留可引用原文？ | selected spans、token budget、drop reason | lost in the middle、压缩丢否定条件 |
| 9 Answer/citation | 每个关键 claim 是否被当前版本 span 支持？ | claim -> source/version/page/chunk/quote | 伪引用、证据不支持、该拒答时硬答 |
| 10 Eval/operate | 质量、安全、时效、延迟、成本是否共同过门？ | dataset/config/trace/cost/release versions | 平均分掩盖 critical failure、cache 陈旧 |

不可颠倒的故障优先级：**越权/注入 -> 数据不存在 -> 解析损坏 -> 切块 -> 表征/查询 -> 召回/重排 -> 打包/生成 -> 成本**。安全故障必须先阻断，不能靠提高答案分数抵消。

## 3. 二十五条提升路径

### 3.1 数据、解析与切块

| 方法 | 何时用 | 最小消融 | 主要风险与回滚 |
|---|---|---|---|
| 权威来源与版本契约 | 知识库无答案、旧版命中 | 三版本同文档、重复上传、时效问题 | 无 source/version/tenant/time 就隔离 |
| 版式感知解析 | PDF 表格、公式、阅读顺序丢失 | 50 页 golden set 比 text/OCR/layout | 不支持格式转专用 parser 或人工复核 |
| 去重、来源与有效时间 | 重复引用、冲突、缓存错命中 | content hash/canonical URL/version 变更 | 关键 metadata 缺失不入库 |
| Fixed/recursive/structural | 建立可解释 baseline | chunk size/overlap 网格，其他固定 | 复杂方案无显著增益即回滚 |
| Parent-child/window | 小块命中但条件不完整 | child 256/512 × parent 2k/4k | parent 过大造成中间遗忘，缩小或回结构块 |
| Semantic chunking | 结构不稳定且语义边界更重要 | 与 structural 同索引同评测对照 | 阈值敏感、成本高；2026 对照未显示稳定胜出 |
| Contextual/late chunking | 短块脱离主体和章节 | original/contextual/late 三路 | 生成上下文可能漂移，引用必须回原文 |
| RAPTOR 层级摘要树 | 长文全局主题失败 | flat chunks vs tree retrieval | 摘要无原文指针不得作为最终证据 |

### 3.2 表征、查询与召回

| 方法 | 何时用 | 最小消融 | 主要风险与回滚 |
|---|---|---|---|
| Dense baseline | 同义表达漏检 | 通用/多语/领域模型 shadow index | 精确 ID、数字、时间常失败；读别名回旧索引 |
| BM25 + dense + RRF | SKU、错误码和语义问题并存 | BM25/dense/RRF/weighted fusion | 两套索引和调权成本；不胜单路就关闭融合 |
| ColBERT/multivector | 单向量无法覆盖多个 token 条件 | single-vector top100 vs ColBERT top20 | 索引与 p95 超预算则回 dense + rerank |
| 领域/多语 embedding | 内部术语和跨语种切片失败 | 通用 vs multilingual vs domain | 禁止原地覆盖，影子索引通过后切别名 |
| Normalize/multi-query/HyDE | 查询省略、同义词、零样本迁移 | 原 query/规则标准化/multi-query/HyDE | 改写会造实体；低置信保留原问或澄清 |
| Decomposition + routing | 多跳只找到一段，简单问却走贵路径 | simple/single-hop/multi-hop 路由 | 分类错走错路；低置信回 hybrid + rerank |
| ACL pre-filter | 多租户或资源授权 | tenant A/B 同文 canary 互查 | 任一跨租户候选即阻断发布 |
| Cross-encoder rerank | top-k 含答案但排名靠后 | top50/100 -> rerank top5/10 | 超时回确定性排序并降低置信 |
| GraphRAG/LightRAG | 实体关系、全局主题、跨文档综合失败 | vector/decomposition/graph local/global | 抽图错、实体爆炸、索引贵；保留 passage 证据 |
| MMR/diversity | 重复 chunk 挤掉互补证据 | 固定候选池消融 lambda | 过度多样会降相关性，回 relevance-only |

### 3.3 上下文、生成与治理

| 方法 | 何时用 | 最小消融 | 主要风险与回滚 |
|---|---|---|---|
| 证据打包、去重与重排 | 检索对但模型忽略中间证据 | original/reorder/extractive/LLM compression | 压缩丢引用时回原文 span |
| Claim-level citation | “有引用”但引用不支持结论 | 人标 claim-evidence + 篡改引用集 | judge 也会错；关键 claim 无 span 就删或拒答 |
| Self-RAG/CRAG/corrective | 检索失败仍硬答 | baseline/一次纠错/受限循环 | 评估器误判与循环成本；无证据必须拒答 |
| ColPali/page-image | 图、表、公式无法由 OCR 保真 | OCR/page image/mixed route | 无页或区域定位不生成精确结论 |
| 版本化 cache/增量索引 | 陈旧答案和索引延迟 | 逐一变更 source/model/index/policy | source 新于 index 时 bypass 或 rebuild |
| 注入/投毒隔离 | 文档诱导泄密、工具调用或伪装权威 | 指令 chunk、伪文档、canary secret | 检索内容永远是不可信数据；隔离后重建派生物 |
| 分层 eval/trace/cost gate | 优化后不知哪层变好 | 固定集 + slice + trace + shadow release | LLM judge 不得覆盖 ACL、泄漏和副作用断言 |

## 4. 症状到最小动作

| 观察信号 | 第一动作 | 必看指标 | 上线结论 |
|---|---|---|---|
| authoritative answer 不在 corpus | 修 source coverage | corpus coverage、index lag | 实验，禁止调模型掩盖 |
| 表格 cell 错位 | 修 layout parser | table cell F1、page anchor | golden set 过门再重建索引 |
| 定义与例外分块 | structural/parent-child 消融 | context recall、citation span | 只切失败文档族 |
| SKU/编号被 dense 漏掉 | hybrid + RRF | exact recall、precision@5 | 胜过两条单路才保留 |
| top-k 有答案但靠后 | rerank | MRR、p95、timeout | 必须有 fallback |
| 多跳缺一段 | 先 decomposition，再测 graph | path coverage、edge precision、成本 | Graph 不是默认依赖 |
| claim 无支持 span | claim validation 或拒答 | unsupported claims、citation precision | critical，阻断 |
| 跨租户候选出现 | 检索前 ACL | cross-tenant leak | critical，立即阻断 |
| 文档含恶意指令 | 隔离来源与全部派生物 | attack success、poison hit@k | critical，立即阻断 |
| cache 返回旧政策 | 版本化失效 | staleness、wrong cache hit | critical，阻断 |
| p95 超预算 | 复杂度路由和预算 | p95、cost/query、质量切片 | 质量与安全不退化才发布 |

仓库提供确定性诊断器，规则采用 fail-closed schema：

```powershell
cd "agent-runtime-gateway\20-源码"
python -m pytest ..\21-测试\test_rag.py ..\21-测试\test_rag_diagnostics.py -q
python -m agent_course.cli eval ..\22-评测集\s3-rag-baseline.json
python -m agent_course.cli rag-diagnostic-eval ..\22-评测集\rag-diagnostic-baseline.json
```

诊断集覆盖 14 类故障、16 个 case 和 64 条显式断言，其中包含“关键阻断信号 + 普通质量症状”的组合回归。它验证“看到信号先改哪一层”，不声称替代真实 retriever、LLM 或生产 red team。

## 6. 工业最佳实践

1. **先固定 baseline**：语料、问题、gold evidence、chunk/index/model/prompt 版本和成本预算都可复现。
2. **先过滤再排序**：tenant/resource ACL、deleted、TTL、effective time 是硬过滤，不是可被相关性覆盖的特征。
3. **一改一验**：每次只改变一个主要变量，并按失败切片报告，不看单一平均总分。
4. **原文是证据根**：摘要、图边、改写、HyDE 和压缩都保留回到 source version + span 的指针。
5. **索引可回滚**：新 embedding/chunk/graph 使用 shadow index、版本化 alias 和 canary query，禁止原地覆盖。
6. **关键失败不平均**：cross-tenant、unsupported critical claim、注入成功、stale policy 和删除后可召回应直接 block。
7. **自动 judge 要校准**：先用人标集测 judge 的一致性、偏差和篡改敏感度；安全边界用确定性断言。
8. **复杂路径按需路由**：GraphRAG、ColBERT、多模态、corrective loop 和 LLM compression 只服务已证明的切片。
9. **全链路可观测**：trace 保存 original/rewrite、ACL、候选、rank delta、selected spans、claim citation、fallback、版本、延迟和成本。
10. **失败进入回归集**：线上事故先最小化和脱敏，再归入 data/parse/retrieval/security/freshness 等稳定 failure taxonomy。

最小发布包：`dataset_version + source_snapshot + parser/chunk/index/model/prompt/policy versions + per-slice metrics + critical assertions + latency/cost + rollback alias + owner`。

## 7. 常见误区

| 误区 | 为什么错 | 正确动作 |
|---|---|---|
| “召回差就换 embedding” | 数据可能不存在或解析已损坏 | 先查 corpus coverage 与 parse fidelity |
| “chunk 越语义化越好” | 阈值和模型敏感，简单策略常是强基线 | 在同一评测上做 structural 对照 |
| “top-k 越大越好” | 增噪、增 token，且不能补语义连接 | 先查 recall，再用 parent/rerank/MMR |
| “有 URL 就算有引用” | URL 可能不支持具体 claim，版本也可能错 | claim -> version/page/chunk/span 校验 |
| “GraphRAG 比 vector 高级” | 它解决关系/全局问题，也带来抽图和索引风险 | 先 decomposition，图只服务明确失败切片 |
| “LLM judge 通过即可上线” | judge 会偏，且平均分可掩盖泄漏 | 人标校准 + deterministic critical gate |
| “生成后删掉越权内容即可” | 未授权数据已进入候选、context、trace/cache | 检索前 ACL 硬过滤 |
| “缓存只按 query” | 数据、权限和模型变化后会复用旧结果 | key 绑定 source/index/model/prompt/policy 版本 |

## 8. 五道自测

1. 文档存在，但解析后的表格把“金额”和“币种”错配。第一动作是什么？
   **答案**：修解析并建立 cell/page golden set。误区：rerank 不能恢复已被破坏的证据。
2. `ZX-1049-B` 从 dense top-k 消失，而自然语言问题表现正常。最小实验是什么？
   **答案**：BM25、dense、RRF 三路消融。误区：精确标识符不是单向量的强项。
3. 多跳问题失败时为什么不直接上 GraphRAG？
   **答案**：先做 query decomposition，证明普通 passage 路径仍缺关系/全局覆盖，再测图的净收益和边精度。
4. citation URL 正确，但句中有一项数值未出现在引用 span。能否发布？
   **答案**：关键 claim 不能发布；删除、降级或拒答。误区：“来源相关”不等于“结论被支持”。
5. 相关性显著提升，但出现一次跨租户候选。如何判定？
   **答案**：阻断发布，修复检索前 ACL 并重跑派生 cache/trace 泄漏检查；质量分不能抵消授权失败。

## 9. 一页速记与预习核对

**速记**

- 顺序：source -> parse -> chunk -> index -> query -> retrieve -> rerank -> pack -> claim/citation -> operate。
- 默认：versioned source + layout golden + structural chunks + ACL pre-filter + hybrid + rerank + claim citation + abstention。
- 升级：失败切片先证明，再引入 semantic/late、ColBERT、graph、corrective 或 multimodal。
- 阻塞：cross-tenant、injection success、unsupported critical claim、stale critical evidence、delete resurrection。
- 发布：固定版本、单变量消融、分片指标、critical gate、shadow/canary、可回滚 alias。

**预习核对**

- [ ] 能指出权威来源、租户边界、有效时间和更新负责人。
- [ ] 有至少 20 个 gold query 与 gold evidence，其中包含表格、无答案、时效和越权样例。
- [ ] 能独立测 parse、retrieval、ranking、citation，而非只看最终回答。
- [ ] 当前 chunk/index/model/prompt/policy 版本可复现。
- [ ] 能运行本仓库 S3 单测、基础 eval 与诊断 eval。
- [ ] 已定义 p95、cost/query、freshness、attack success 和 rollback 条件。

## 10. 2026 证据与未来走向

**已有证据支持**

- 2026 chunking 对照在其设定中没有发现 cluster semantic chunking 超过简单策略，并指出自动 faithfulness 指标的可靠性限制。因此课程把简单可解释 baseline 和人标校准放在首位。
- 2026 secure RAG taxonomy 将风险分为检索前污染、检索时访问操纵、下游 context 利用和知识外泄，说明安全不能只在 prompt 层补丁式处理。
- Docling、GraphRAG、LightRAG、NeMo Retriever 等当前源码将 parse、chunk、index、query、cache、eval 拆成独立责任面，支持模块化影子发布与回滚。
- ColPali 类工作直接检索页面视觉表征，表明 OCR-only 不再是复杂 PDF 的唯一入口。

**基于证据的工程推断，仍需验证**

- RAG 将从固定 pipeline 变为受 policy 控制的 evidence orchestrator，按权限、时效、复杂度、模态和成本选择路径。
- embedding、chunk、graph、cache 频繁变化后，shadow index、read alias 和 canary query 会成为标准发布能力。
- 引用将从 document URL 收紧为 claim-span provenance，并与 ACL decision、版本和有效时间一起审计。
- RAG 与 Agent Memory 会共享 provenance、ACL、删除和评测基础设施，但必须保持 knowledge、user fact、run state 和 procedural experience 的存储边界。
